# סבב תיקון 1: החלטות Orchestrator (גוברות על הדוחות)

מקורות: `_qa/ai-detector.md` (ציון 6/10, חוסם), `_qa/content-creative.md`, ובהמשך `_qa/visual-a11y.md`, `_qa/perf-seo.md` (אם קיימים כשאתם מתחילים — קראו גם אותם ותקנו את מה שנוגע לעמודים שלכם).

## מה כבר תוקן ברמת המערכת (אל תעשו שוב)
- `[לאשר]`/`[לאמת]` מוסתרים אוטומטית מחוץ למצב סקירה (`?review` / `#review`). `[למלא]` נשאר גלוי, בגודל קבוע וקטן. עדיין: **צמצמו [למלא] שאינם הכרחיים** ואל תשימו [למלא] בכותרות.
- טלפון: כש-config.js בלי מספר, כל `.tel-link` ו-`[data-phone-only]` מוסתרים. **עטפו כל שורה כמו "או התקשרו: <tel>" ב-`data-phone-only`** כדי שלא תישאר מילה תלויה.
- כפתורים שטוחים, לוגו חדש, מספרי צעדים בעיגול קטן, גרשיים עבריים (״ ׳) מומרים אוטומטית בטקסט הגלוי, הערות HTML מוסרות מהפלט, שורת רישיון אחידה בפוטר ובנכסים.
- דף הבית שוכתב (ראו `_src/pages/index.html` כדוגמה לסבב הזה): בלי eyebrows מיותרים, רכיב `figure.photo-slot` במקום דיוקן X, `dl.title-block` מתחת לשרטוט הפתיחה, רשימת דלתות, `.legend`.

## החלטות לכל העמודים
1. **eyebrow** (`p.eyebrow`) נשאר רק כשיש בו מידע: "גילוי נאות", "עודכן באוקטובר 2026", "תיק בניין מס' 404", "גיליון עסקה", "שאלות נפוצות · נכון לאוקטובר 2026". את כל השאר מוחקים.
2. **H1 פנימי:** ביטוי ה-SEO עובר ל-`<span class="h1-kicker">` בתוך ה-H1, והשורה הגדולה היא משפט:
   - sell: kicker "למכור או להשכיר דירה בשרון" + "מחיר שמתאים גם לדירה וגם לבניין שלה"
   - urban-renewal: kicker "התחדשות עירונית ופינוי-בינוי בשרון" + "לפני שחותמים מול יזם"
   - invest: kicker "השקעות נדל"ן בשרון ובכל הארץ" + "כל דירה נבדקת במספרים לפני שמתחייבים" + [לאשר] בגוף, לא בכותרת
   - properties: kicker "דירות ובתים למכירה ולהשכרה" + "מה שאנחנו משווקים עכשיו"
   - about: kicker לפי ה-H1 הקיים מה-seo + משפט קצר משלכם שאינו טענה מומצאת (למשל "שני אנשים, משרד אחד בשרון").
3. **משבצת כותרת** (`dl.title-block`, ראו index) מתחת לשרטוט הפתיחה בכל עמוד: גיליון 02 נכסים · 03 למכור או להשכיר · 04 התחדשות עירונית · 05 השקעות · 06 אבא ובן · 07 הצהרת נגישות (מתוך 07). ב-404: "גיליון 404 · הוחזר לתיקון". שדות: גיליון / עמוד / קנ״מ ("להמחשה") / עודכן (14.10.2026).
4. **לשבור את התבנית "כותרת בעמודה צדדית + רשימה ממוספרת/אקורדיון":**
   - sell "שישה צעדים" → טבלה `שלב | מה קורה | מי | מה נצטרך מכם` (`.table-wrap > table.table`), עמודת "מי" = `[למלא: האב / הבן / שנינו]`.
   - FAQ ב-sell וב-properties → עמודה אחת ברוחב מלא (H2 מעל, `.faq` מתחת), בלי עמודה צדדית.
   - invest "ככה עובד ליווי" → `ol.timeline` אופקי.
   - מספור רק בצירי זמן ובגיליון: ב-404 (קישורים), about (כללים), urban-renewal (שאלות ליזם) → `ol.numbered.numbered--plain` או רשימה בלי מספרים.
5. **פתיחות שונות** (לא אותו hero בכל עמוד): properties — H1 קטן יחסית והרשימה עצמה גלויה מעל הקפל ב-1440×900; invest — הפתיחה כוללת את 4 השורות הראשונות של גיליון העסקה; urban-renewal — שרטוט ברוחב מלא וה-H1 יושב על קו הקרקע שלו (אם כבר כך, השאירו). sell — כמו שהוא.
6. **קופי:** ליישם את כל ההחלפות המדויקות מ-ai-detector.md (סעיף "קופי") ומ-content-creative.md (סעיף א') לעמודים שלכם. כלל כפתורים: **ציווי רבים** ("כתבו לנו", "שאלו", "ספרו לנו", "שלחו"), "או התקשרו:". "דף הבית" בפירורי לחם (במקום "ראשי"). "פינוי-בינוי" עם מקף בטקסט גלוי. "צפייה" ולא "סיור". "רכז הנגישות". "ביתא, בארמית: הבית." נוסח אחד. "עסק נדל"ן משפחתי".
7. **CTA בתוך תוכן ארוך:** urban-renewal אחרי הטבלה ואחרי ציר הזמן; invest מתחת לגיליון; about מתחת לפתיחה (נוסחים ב-content-creative.md).
8. **about:** מקטעי "על מה אנחנו מתווכחים" ו"מה לא נעשה" מקבלים `hidden` (השאירו הערה בקוד המקור). H2 "מי אנחנו" במקום שמות כ-[למלא]. הדיוקנאות → `figure.photo-slot` (העתיקו מ-index). שם הפירור ב-JSON-LD: "אבא ובן". מילת "ביתא" הענקית: או כולה בתוך המסך או חריגה מכוונת נקייה, לא חתוכה ב-375.
9. **JSON-LD:** invest — שם השירות "ייעוץ והשקעות נדל"ן". FAQPage רק אם התשובות נקיות לחלוטין מ-[...] — אחרת בלי.
10. אסור: hex בקבצי CSS, עריכת site.css / tokens.css / main.js / build.py (בקשו ממני בדוח), המצאת עובדות.
